# AGENT-frontend整体技术规约

## 1 适用范围

约束 `frontend/` 目录内的全部内容：页面、组件、接口调用、类型定义、构建配置。不涉及 Unity 客户端与后端实现。

## 2 与其他规约的关系

- 技术栈、跨端契约、目录纪律、提交规范见 `../AGENT-整体技术规约.md`。
- 接口路径、状态码、错误码、枚举取值见 `../docs/需求规格说明书.md` 第 5、6 章；本文件只写本端怎么用。
- 状态迁移规则归后端，本文件第 6 节只描述如何提交与回显。

## 3 技术栈与依赖

- React 19 + TypeScript + Vite，包管理使用 npm。
- 运行时依赖保持 `react`、`react-dom` 两项；新增运行时依赖需在提交说明中写明用途与不引入的替代方案。
- 不引入 UI 组件库与 CSS 框架，样式用内联样式或组件级 CSS 文件。
- TypeScript 严格模式保持开启（`tsconfig.json` 中 `strict: true`），关闭需单独说明理由。

## 4 目录与分层

| 路径 | 职责 |
| --- | --- |
| `src/api/` | 后端调用封装，`client.ts` 是唯一的网络出口 |
| `src/components/` | 可复用展示组件（问题表格、状态选择器、提示条） |
| `src/pages/` | 页面级组件，负责取数与状态编排 |
| `src/types/` | 与后端契约对应的类型定义 |
| `src/App.tsx` | 布局与页面入口 |
| `public/` | 不参与编译的静态资源 |

依赖方向为 `pages → components → api`；`components/` 不直接取数，`api/` 不引用 React。

## 5 编码约定

- 组件统一写成函数组件，Props 使用显式 `interface` 声明。
- 类型只在 `src/types/issue.ts` 定义一次，其他文件从此处导入；禁止 `any`，外部数据先按 `unknown` 收窄。
- 状态值与优先级值使用 `IssueStatus`、`IssuePriority` 联合类型，不在组件里重复写字符串字面量。
- 网络请求一律调用 `src/api/client.ts` 的 `apiRequest<T>`，由它统一拼接 `API_BASE_URL`、设置 `Content-Type`、把错误响应转成 `Error`。
- 后端基址只从 `import.meta.env.VITE_API_BASE_URL` 读取，缺省为空串：请求走同源 `/api`，由 `vite.config.ts` 的 `server.proxy` 转发到 `http://localhost:8080`。
- 组件内不出现 `fetch`，不出现硬编码的后端地址。

## 6 契约与数据

**列表**：页面加载时调用 `GET /api/issues`，一次取全量，按后端返回顺序渲染，前端不重排、不本地排序。

**视图状态**：四种状态互斥，同一时刻只渲染其中一种。

| 状态 | 触发条件 | 渲染内容 |
| --- | --- | --- |
| 加载中 | 请求进行中 | 加载提示 |
| 有数据 | 响应 200 且数组非空 | 问题列表 |
| 空 | 响应 200 且数组为空 | 含「暂无问题」的空状态 |
| 错误 | 网络错误、超时、HTTP 5xx | 含「加载失败」的提示与重试按钮，页面框架保留 |

错误状态下不渲染空状态文案，避免把服务异常显示成没有数据。

**列表字段**：至少展示标题、优先级、状态，并展示坐标；缺失的可选字段显示占位文案而不是留空。

**状态修改**：调用 `PATCH /api/issues/{id}/status`，请求体只有 `status`。

- 成功后以响应体覆盖该行数据（含 `updatedAt`），不做本地推测。
- 失败时该行回退到修改前的值，并显示含「状态修改失败」的提示。
- 提交进行中该行控件不可再次触发。

**刷新**：页面提供刷新操作重新拉取列表；不引入轮询或实时推送。

## 7 验证方式

| 命令 | 通过标准 |
| --- | --- |
| `npm run build` | `tsc --noEmit` 无错误，且产出 `dist/` |
| `npm run dev` | 页面在 `http://localhost:5173` 正常打开 |

手动验证项：

| 场景 | 预期 |
| --- | --- |
| 后端未启动时打开页面 | 显示「加载失败」与重试按钮，页面不白屏 |
| 后端启动后点重试 | 列表正常加载，错误提示消失 |
| 后端无数据 | 显示「暂无问题」 |
| 修改某条状态为 `resolved` | 该行状态更新，`updatedAt` 变化 |
| 修改状态时后端不可用 | 该行回退原状态并提示失败 |

当前没有 lint 脚本与测试脚本；新增时同步更新 `package.json`、`README.md` 与本表。

## 8 禁止事项

- 在组件内直接调用 `fetch` 或拼接后端地址。
- 在 `src/types/` 之外重复定义 `Issue` 或复制枚举字面量。
- 在前端实现状态迁移校验或过滤掉某些目标状态。
- 对 `location` 的坐标做换算、取整或重新排序展示。
- 用 `any` 或类型断言掩盖后端返回结构与类型定义不一致的问题。
- 在请求失败时静默吞掉错误、只留空白页面。
