# AGENT-unity整体技术规约

## 1 适用范围

约束 `unity/` 目录内的全部内容：场景搭建、C# 脚本、预制体、上报逻辑。不涉及管理端与后端实现。

## 2 与其他规约的关系

- 技术栈、跨端契约、目录纪律、提交规范见 `../AGENT-整体技术规约.md`。
- 接口字段、错误码、状态取值见 `../docs/需求规格说明书.md` 第 5、6 章；本文件不复述。
- 本端只在第 6 节引用契约结论，字段名以规格说明书为准。

## 3 技术栈与依赖

- Unity LTS + C#，工程根为 `unity/`，由 Unity Hub 打开。
- 只使用 Unity 内置模块与内置几何体（Cube、Plane、Cylinder、Sphere）；不引入需要额外下载的美术资源、第三方控制器或网络库。
- 网络请求使用 `UnityEngine.Networking.UnityWebRequest`。
- `Packages/`、`ProjectSettings/` 由 Unity 生成，不手工编辑其中的文件。

## 4 目录与分层

| 路径 | 存放内容 |
| --- | --- |
| `Assets/Scripts/` | 全部 C# 脚本，一个脚本一个职责 |
| `Assets/Scenes/` | 场景，主场景固定命名为 `Main.unity` |
| `Assets/Prefabs/` | 预制体，问题标记做成预制体供实例化 |
| `Assets/Materials/` | 材质资源 |
| `Packages/`、`ProjectSettings/` | Unity 生成的工程配置 |

脚本按职责拆分，禁止把多个职责写进同一个文件：

| 职责 | 约定文件名 | 说明 |
| --- | --- | --- |
| 相机移动与俯仰 | `CameraRigController.cs` | 只处理输入与变换，不接触业务数据 |
| 射线拾取 | `SceneClickPicker.cs` | 只在命中时对外抛出命中点 |
| 标记管理 | `IssueMarkerManager.cs` | 创建、替换、销毁标记 |
| 表单与提示 | `IssueFormUI.cs` | 字段读写、本地校验、结果提示 |
| 接口调用 | `IssueApiClient.cs` | 唯一发起 HTTP 请求的地方 |
| 序列化类型 | `IssueModels.cs` | 与契约字段一一对应的 `[Serializable]` 类 |

文件名与类名一致；新增脚本按上表职责归位，职责不在表内时先在表中补一行。

## 5 编码约定

- 类名与文件名用 PascalCase；私有字段 camelCase；序列化字段与契约同名，使用 camelCase。
- 命名空间统一为 `Unity3DInspection`，按职责可加子命名空间 `Unity3DInspection.Network`。
- 场景对象命名能读出用途：`Floor`、`Wall_North`、`Cabinet_A`、`Cabinet_B`。
- 每个可点击对象挂载 Collider；标记对象不挂 Collider，避免被射线再次命中。
- 点击处理入口先用 `EventSystem.current.IsPointerOverGameObject()` 判定指针是否落在界面元素上，命中界面则直接返回，不进入射线检测。
- 左键专用于射线拾取，视角拖动使用右键拖动，两种输入不共用按键。
- 相机平移限制在地面覆盖范围内，俯仰角限制在 -80° 至 80°。

## 6 契约与数据

- 上报字段：`title`、`description`、`priority`、`location`（含 `x`、`y`、`z`）。`id`、`status`、`createdAt`、`updatedAt` 由服务端生成，客户端不发送。
- `title` 去除首尾空白后为空时在本地拦截，提示「标题不能为空」，不发起请求。
- `priority` 默认选中 `medium`，三档取值为 `low`、`medium`、`high`。
- `location` 取 `RaycastHit.point` 的世界坐标，原样上报，不做单位换算或轴向调整。
- 后端基址集中定义在一处常量，默认 `http://localhost:8080`。
- 提交返回 201 时提示含「提交成功」，随即销毁标记、清空表单、关闭面板。
- 提交返回非 2xx、超时或网络错误时提示含「提交失败」，保留标记与已填内容，允许再次提交。
- 请求进行中提交按钮不可再次触发。

**标记生命周期**

- 有效点击后创建标记，位置等于命中点世界坐标。
- 场景中同一时刻至多保留一个待提交标记；已有标记时再次有效点击，销毁旧标记并在新命中点创建。
- 点击取消或关闭表单，销毁标记且不发送请求。
- 提交成功后销毁标记；提交失败保留标记，直至用户取消或下次提交成功。
- 已保存到后端的问题不在场景中生成标记。

## 7 验证方式

- 在 Unity 编辑器中编译工程，Console 无编译错误。
- Play 模式手测清单，逐项确认：

| 场景 | 预期 |
| --- | --- |
| 键盘移动、右键拖动 | 相机在场景内移动并转向，俯仰不翻转 |
| 点击两台不同机柜 | 两次命中点坐标不同，标记出现在点击处 |
| 点击界面按钮或输入框 | 不产生标记，不打开新表单 |
| 连续点击多处表面 | 场景中始终只有一个标记，坐标随之更新 |
| 标题留空提交 | 提示「标题不能为空」，无请求发出 |
| 后端关闭后提交 | 提示「提交失败」，标记与输入内容仍在 |
| 后端开启后提交 | 提示「提交成功」，标记消失，管理端可查到该问题 |

- 自动化测试：当前未引入 Unity Test Framework，暂不作为通过条件；引入后在 `README.md` 与本文件补充运行命令。
- 当前开发机未安装 Unity 编辑器，上述验证需在装有 LTS 版本的环境中执行，未执行时在提交说明中标注。

## 8 禁止事项

- 在界面事件（按钮点击、输入框提交、下拉选择）里创建标记。
- 用界面坐标反推世界坐标作为标记位置。
- 在客户端缓存或推断问题列表与状态。
- 在客户端实现状态迁移规则，或提前把状态置为非 `open`。
- 绕过 `IssueApiClient.cs` 在其他脚本里直接发请求。
- 使用 `GameObject.CreatePrimitive` 生成标记以外的场景物件时忘记关闭或移除多余 Collider。
